# ADRs da execução AURION v5.0 / Especificação de Engenharia v6.0

Referências: *Prompt Mestre Unificado AURION v5.0* (04/10/2026) e *Especificação de Engenharia e Arquitetura v6.0* (05/10/2026).
Precedência aplicada: decisão explícita do proprietário (06/10/2026) > segurança/regulação > v6.0 > v5.0.

---

## ADR-0005 — Modular monolith em Cloudflare Workers + D1 (desvio registrado da stack Next.js/FastAPI/PostgreSQL)

**Status:** aceito · **Data:** 2026-10-06 · **Responsáveis:** Bruno Antunes Andrade (proprietário), engenharia

**Contexto.** A v6.0 congela Next.js + FastAPI + PostgreSQL + Redis + S3. Isso exige hospedagem paga. Em 06/10/2026 o proprietário decidiu
implementar **todos os requisitos funcionais na base atual** (API em Cloudflare Workers + banco D1, front ES modules no GitHub Pages), sem custo de infraestrutura.

**Decisão.** Manter o modular monolith na base atual, com módulos por domínio e dependências unidirecionais:
`worker/src/shared.js` (utilitários), `identity.js`, `index.js` (composição e rotas legadas) e motores puros em `apps/web/app/js/*_engine.js`
compartilhados entre API e testes. Os contratos de API seguem `/v1/...` (a v6.0 pede `/api/v1` — o prefixo será mapeado na migração).

**Alternativas.** (a) Migrar já para FastAPI/PostgreSQL — rejeitada agora por custo; (b) manter o protótipo Python em `services/` como produção — rejeitada (sem hospedagem gratuita compatível).

**Consequências.** + custo zero, deploy automático, latência baixa. − limite de CPU por requisição (10 ms no plano gratuito): uploads em formato binário, cálculos leves;
jobs pesados vão para GitHub Actions (ADR-0012). − D1 no lugar de PostgreSQL (sem RLS nativo): isolamento por `user_id` em toda consulta + testes de acesso cruzado.

**Plano de migração.** Os motores são funções puras sem dependência de plataforma; a troca para FastAPI/PostgreSQL reaproveita regras, testes e contratos. Gatilho: orçamento aprovado ou limites do plano gratuito atingidos.

## ADR-0006 — PWA instalável em vez de extensão de navegador

**Status:** aceito · **Data:** 2026-10-06 — `app/manifest.webmanifest` + `app/sw.js`. O service worker guarda só a casca estática do app;
respostas da API e arquivos de `data/` nunca são guardados (dado sensível fora de cache local).

## ADR-0007 — Identidade: e-mail ou CPF, MFA TOTP, sessões e auditoria encadeada

**Status:** aceito · **Data:** 2026-10-06

- CPF nunca é guardado em claro: índice por HMAC-SHA256 com *pepper* gerado no primeiro uso e guardado no D1; exibição mascarada.
- MFA por TOTP (RFC 6238) com segredo cifrado (AES-GCM, chave interna), 8 códigos de recuperação de uso único, bloqueio de reuso do mesmo passo.
- Recuperação de senha com token de uso único (30 min) e resposta idêntica para conta inexistente. Envio por e-mail via adapter (Resend) **desligado** até os secrets
  `RESEND_API_KEY` e `MAIL_FROM`; enquanto isso, o administrador gera um link de 24 h no CRM.
- Sessões com dispositivo e local aproximado (sem IP completo — minimização LGPD), encerramento individual ou em massa; troca de senha encerra as demais.
- `audit_log` por titular, encadeado por hash (`prev_hash` → `hash`); qualquer alteração quebra a cadeia, verificada a cada leitura.

## ADR-0008 — Tax Engine determinístico, versionado e reproduzível

**Status:** aceito · Regras em `tax_engine.js` (`RULES`, com código, versão e fontes), espelho do motor Python validado; chave de reprodutibilidade
= hash(entradas + versões das regras + versão do motor). A IA nunca calcula nem altera regra. Excel é artefato de auditoria gerado a partir do mesmo resultado.

## ADR-0009 — Trader Intelligence sem execução de ordens

**Status:** aceito · Nenhuma rota `submit_order`, `cancel_order`, `replace_order`, `broker_execute` ou equivalente. Teste automático varre o código da API
e falha se aparecer. Operações registradas/importadas formam um único `TradeRecord` que alimenta Finanças, Imposto e Trader.

## ADR-0010 — Public Disclosures somente com dados públicos e rastreáveis

**Status:** aceito · Fonte: Portal de Dados Abertos da CVM (documentos IPE de companhias abertas). Cada registro guarda fonte, data de publicação,
protocolo e link do documento. Nunca é rotulado como "sinal" ou prova de uso de informação privilegiada.

## ADR-0011 — Power BI Embedded como camada analítica opcional (desligada)

**Status:** aceito · O backend continua fonte de verdade. O adapter de embed fica pronto e só é ativado com `PBI_TENANT_ID`, `PBI_CLIENT_ID`,
`PBI_CLIENT_SECRET`, `PBI_WORKSPACE_ID` e `PBI_REPORT_ID`; sem eles, as visões expandidas usam os gráficos próprios do app.

## ADR-0012 — Jobs pesados e coleta de dados públicos no GitHub Actions

**Status:** aceito · Coleta de divulgações da CVM, notícias de fontes públicas (RSS) e eventos rodam em workflow agendado gratuito, que publica JSON estático
versionado no próprio site. Mantém o Worker dentro do limite de CPU e deixa a origem auditável pelo histórico do Git.

## ADR-0013 — Integrações pagas prontas e desligadas

**Status:** aceito (decisão do proprietário, 06/10/2026) · Pluggy (Open Finance), Resend (e-mail), Power BI Embedded, provedor de voz (TTS) e provedores
de notícias licenciadas: adapter + simulador + testes; ligam ao cadastrar os secrets. Alternativas gratuitas ativas: voz do próprio navegador, notícias de RSS públicos.

## ADR-0014 — Copilot com ferramentas determinísticas e filtro de segurança

**Status:** aceito · Fluxo intenção → roteador → serviço de domínio → resultado estruturado → explicação → filtro. Nenhum número sai sem evidência
(fonte e timestamp). Pedidos prescritivos de compra/venda, tentativa de injeção e pedido de credencial são bloqueados antes de qualquer ferramenta.

## ADR-0015 — Professional Hub com leitura delegada auditada
**Contexto.** O cliente quer que o contador ou assessor veja seus números sem compartilhar senha.
**Decisão.** O cliente concede acesso por e-mail, com validade (até 1 ano) e revogação imediata. O profissional usa a própria conta e o cabeçalho `X-Act-As`. O acesso é somente `GET` e só em uma lista fechada de rotas: finanças, patrimônio, alocação, tributação, alertas, eventos, Trader e `me`. Ficam fora segurança, sessões, privacidade, documentos, pagamentos e compartilhamento. Cada leitura grava `profissional.leitura` na trilha encadeada do cliente.
**Consequências.** Não há papel de escrita delegada. Se algum dia houver, será outra ADR com consentimento explícito por ação.

## ADR-0016 — AURION Daily determinístico, notícias por RSS e personalização no aparelho
**Decisão.** O Daily é montado por regras (`daily_engine.js`): mesmas entradas, mesmo texto, sem LLM. A voz usa `speechSynthesis` do navegador. A voz neural (`/v1/voice/tts`) só é usada quando `TTS_API_KEY` existe.
**Notícias.** Vêm de RSS públicos coletados pelo GitHub Actions. Guardamos só título, link, fonte, data e etiquetas, sem o corpo, por direitos autorais. A pontuação "Para você" roda no navegador, e a carteira não sai do aparelho para nenhum terceiro.
**Divulgações.** Vêm da CVM (IPE + FCA para tickers), com protocolo e link do documento original.
